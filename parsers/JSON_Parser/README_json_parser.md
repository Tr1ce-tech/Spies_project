# JSON-профили форума

`json_parser.py` читает `raw_data/FrequentFlyerForum-Profiles.json` потоково. Результаты находятся в `result/`; текущая рабочая директория не влияет на пути по умолчанию.

```bash
.venv/bin/python parsers/JSON_Parser/json_parser.py
.venv/bin/python parsers/JSON_Parser/verify_json.py
.venv/bin/python -m unittest discover -s parsers/JSON_Parser -v
```

Для повторного запуска задайте новую папку: `--output parsers/JSON_Parser/result_new`.

- `json_profiles_part_*.parquet`: 66 592 исходных профиля, весь `raw_profile_json` и метаданные.
- `json_flights_part_*.parquet`: 1 308 987 вложенных наблюдений; все повторы сохранены.
- `json_loyalty_part_*.parquet`: 88 827 записей программ лояльности; поля `Status`, `programm`, `Number`, исходный JSON и ссылка на профиль.
- `json_issues.csv`: 55 751 предупреждение о синтаксисе кода аэропорта. Исходные значения не заменены догадками.
- `json_summary.json`: контрольная сумма, версия, количества, статус завершения.
- `verification.json`: результаты полной сверки другим читателем ijson.

`source_sha256`, `rule_version`, `profile_record_id`, `record_id` связывают результаты с источником. Профили и наблюдения имеют разные единицы. Нормализация имён, сопоставление людей и восстановление реальных перелётов здесь не выполняются.

Повторяющиеся ключи сохраняются в сыром JSON и отмечаются для проверки. При конфликте ключей полей рейса плоские значения не выбираются по принципу «последний победил». В текущем полном источнике повторов ключей не обнаружено. Уже обработанные фрагменты удаляются из входного буфера. Ошибка записи не получает успешный статус.

Чтение всей таблицы:

```python
from pathlib import Path
import pandas as pd

folder = Path("parsers/JSON_Parser/result")
flights = pd.concat(
    [pd.read_parquet(p) for p in sorted(folder.glob("json_flights_part_*.parquet"))],
    ignore_index=True,
)
```

Сравнены все исходные объекты профилей и все поля наблюдений и записей лояльности, а не только небольшая выборка. Это проверка извлечения; достоверность исходных сведений и исторических кодов отдельно не установлена.

Версия `forum.json.v3` добавляет таблицу лояльности. В исходнике первый такой раздел начинается на физической строке 343. Ограничения в 300 строк у парсера нет: физические строки JSON не равны строкам таблицы. Каждый профиль может содержать много наблюдений и карт.

`Number` не переводится в число и не очищается от пробелов. `loyalty_rows` в таблице профилей — число извлечённых элементов массива. Связь таблиц — `profile_record_id`; это идентификатор исходного профиля, а не установленного человека. Поля `NickName`, `Sex`, `Real Name`, `Travel Documents` остаются в `metadata_json` и полном `raw_profile_json`; в отдельные колонки и таблицы они пока не развёрнуты. Все шесть ключей профиля сохранены.

Новая версия сверена независимо с исходником; предыдущий результат v2 сохранён в `legacy/result_v2/`. Сам по себе статус завершения подтверждает техническое сохранение элементов, а не истинность их содержимого. При конфликтующих ключах записи лояльности исходный JSON сохранён, а плоские значения оставлены пустыми со статусом `review`.
