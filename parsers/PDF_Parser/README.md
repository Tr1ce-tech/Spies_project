## Выходные таблицы расписания

| Файл в data/pdf_schedule/ | Единица |
|---|---|
| schedule.parquet | Одна напечатанная строка правила расписания, 40 полей |
| raw_lines.parquet | Любая непустая текстовая строка с классификацией, страницей, колонкой и локальным номером |
| operator_notes.parquet | Явное примечание `Operated by`, исходный текст и ссылка на предшествующую строку |
| quarantine.parquet | Нераспознанная строка и причина; не удаляется |
| pages.parquet | Счётчики для каждой пары страница/колонка |
| manifest.json | Хэш источника, версии, диапазон, счётчики, длительность, статус запуска |
| validation.json | Результаты технической проверки целостности |
| schedule_preview.csv | Только первые 200 строк для просмотра; не полный массив |

`raw_id`/`schedule_id` — уникальный локатор `SHA256:страница:колонка:строка`; колонка 0 — слева, 1 — справа. Ссылки `origin_header_id` и `destination_header_id` ведут к конкретным заголовкам в raw_lines. `source_file`, `source_sha256`, `parser_version` сохранены в каждой первичной/производной текстовой записи.

Одна строка **не равна одному вылету**: она задаёт период и повторяющиеся дни недели. Даты без года получают год только при единственном подходящем интервале внутри периода с обложки. Все времена — местные. Никакой проверки физической длительности по двум местным часам не выполняется.

Обе колонки разбираются независимо. Маршрут берётся из последних явных `FROM`/`TO` той же колонки; новый FROM сбрасывает старое назначение. Статус `explicit_headers` означает заголовки на той же странице, `continued_same_column` — наследование через границу страницы, `incomplete_route` — неполные сведения. Наследованные маршруты помечены и не выдаются за независимо подтверждённые. Географические подписи сохраняются буквально, без назначения страны/города/часового пояса по внешнему справочнику.

Звёздочка в номере рейса сохраняется; оператор не выводится из неё. Доступно только буквальное `operator_raw` из явных примечаний. Привязка к предшествующему рейсу имеет собственный статус, включая перенос со страницы. При нескольких примечаниях не выбирается одно удобное значение.

`field_issues` фиксирует неоднозначности, включая `+-1` в дате прибытия. Для этого маркера нормализованное смещение остаётся пустым. Неизвестный справочнику код оборудования сохраняется с `aircraft_dictionary_status=not_listed_in_intro` — это не доказательство ошибки кода.

Повторы из PDF сохраняются со всеми локаторами. Сообщение `Consult your travel agent for details` учитывается как сообщение об отсутствии деталей и не превращается в рейс. Нулевой карантин не доказывает отсутствие ошибок. Историческая достоверность расписания и все перенесённые маршруты независимо не проверены.

Парсер пишет Parquet порциями по 20 000 строк, не накапливая весь результат в RAM. Notebook по умолчанию читает выбранные колонки. При работе с маленькими примерами можно использовать обычные CSV; полный Parquet сохраняет типы и позволяет фильтрацию при чтении.

## Как устроено извлечение

1. Считается SHA-256 всего PDF, но текст читается только со страниц 1–4.
2. PyMuPDF возвращает текстовые строки и координаты. `raw_text` сохраняется без исправлений; `text` отличается только удалением пробелов по краям.
3. На странице 2 колонки разделяются по координатам. Это предотвращает склеивание контактов и Disclaimer.
4. На странице 3 заголовок поля связывается со следующими строками до следующего заголовка. Карта дней извлекается из явной расшифровки Days.
5. На странице 4 каждая строка разбирается как `код : описание`. Обе колонки учитываются; коды остаются строками.
6. Производные строки содержат страницу, хэш файла, версию парсера, правило и `source_record_ids` — JSON-массив ссылок на raw_lines. Координаты доступны через эти ссылки; отсчёт страниц с единицы, координаты в PDF points.
7. Каждая запись Parquet проверяется обратным чтением через `assert_frame_equal`, включая типы.

Парсер предназначен для этой структуры документа. При отсутствующих обязательных заголовках/непонятных строках справочника он останавливается с ошибкой; поддержка произвольных PDF не заявляется. Исходный PDF не меняется.

## Проверенные особенности и ограничения

- Обложка задаёт период **2018-11-01 — 2019-01-31**.
- В Days: **1 = Sunday, 7 = Saturday**. Нельзя применять номера дней Python без явного преобразования.
- DepTime и ArrTime — **местное время**. `+1` означает прибытие на следующий день. Часовые пояса здесь не заданы.
- В справочнике есть `BUS : Bus`, `EQV : Equipment varies` и обобщённые типы. Не каждый код обозначает конкретную модель самолёта.
- Названия, сайты и описания не исправляются и не проверяются по современным справочникам. Например, извлечённое `Aerolneas Argentinas` сохранено как есть.
- Disclaimer сохраняется целиком: источник предупреждает о возможной неполноте, ошибках и изменении расписания. Это ограничения самого документа, а не инструкции к выполнению проекта.
- Все четыре страницы отрисованы и визуально просмотрены; сверены период, поля, контакты и обе колонки кодов. Проверены ссылки на строки, отсутствие дубликатов ID и сохранение типов.
- Иллюстративная таблица на странице 3 — изображение. **Она не распознана как структурированная таблица**; её наличие и расположение сохранены в images. Логотипы также не транскрибированы. OCR и сбор строк расписания пока не выполняются.
- `not_independently_verified` отличает успешный технический разбор от независимой проверки правильности сведений документа. Визуальный просмотр не подтверждает историческую достоверность расписания.

Разбор самого расписания описан в начале этого README и в notebook `02_pdf_schedule.ipynb`.
