# BoardingData.csv → pandas / Parquet

Отдельный CSV-парсер. По умолчанию читает `../../raw_data/BoardingData.csv` относительно папки скрипта; результаты сохраняет в `result/` рядом со скриптом. Исходный файл не меняется. Другие парсеры и Git не используются.

## Состав

- `parse_csv.py` — разбор CSV и функция `load_records()`.
- `verify_csv.py` — полная сверка байтов и всех полей независимым pandas C-движком.
- `test_parser.py` — тесты граничных случаев на синтетических данных.
- `01_csv_parser.ipynb` — просмотр готовых DataFrame с сохранёнными выводами.
- `requirements.txt` — версии pandas и pyarrow.
- `result/records.parquet` — наблюдения источника, исходные и нормализованные поля.
- `result/raw_records.parquet` — все логические записи после заголовка, исходные байты, текст и список полей. Пустые записи, если встретятся, сохраняются здесь отдельно.
- `result/issues.parquet` — неоднозначности и ошибки с исходным ID и объяснением.
- `result/manifest.json`, `fields.json`, `verification.json` — происхождение, правила, счётчики, схема и проверки.
- `logs/` — результаты запусков и тестов. Подробные таблицы содержат персональные поля и остаются локально.

## Запуск из корня проекта

```bash
.venv/bin/python parsers/CSV_Parser/parse_csv.py
.venv/bin/python parsers/CSV_Parser/verify_csv.py
.venv/bin/python -m unittest discover -s parsers/CSV_Parser -p test_parser.py -v
```

Повторный разбор существующий `result/` не перезаписывает. Для нового запуска:

```bash
.venv/bin/python parsers/CSV_Parser/parse_csv.py --out parsers/CSV_Parser/result_new
```

Можно явно передать другой входной путь первым аргументом. Поддерживается конкретная схема BoardingData, UTF-8 с необязательным BOM, разделитель `;` и кавычки `"`. Неизвестные заголовки отклоняются, кодировка и схема не угадываются. Временные и пользовательские пути не зашиты в код.

Для отдельного окружения: `python -m pip install -r requirements.txt`. Из папки CSV_Parser общий интерпретатор проекта доступен как `../../.venv/bin/python`.

## Чтение

Из корня проекта:

```python
from parsers.CSV_Parser.parse_csv import load_records

df = load_records()
print(df.shape)
```

Из папки CSV_Parser: `from parse_csv import load_records`. Можно выбирать столбцы и применять фильтры Parquet:

```python
df = load_records(
    columns=["flight_date", "flight_time", "flight_number", "destination_text"]
)
```

## Единица и поля

Одна строка основной таблицы — исходное наблюдение о пассажире и рейсе/посадке. Это не подтверждение личности или фактически совершённого перелёта. Строки не сопоставляются и не удаляются как дубли.

| Исходное поле | Нормализованное | Тип |
|---|---|---|
| PassengerFirstName | passenger_first_name | string |
| PassengerSecondName | passenger_second_name | string |
| PassengerLastName | passenger_last_name | string |
| PassengerSex | passenger_sex | string |
| PassengerBirthDate | passenger_birth_date | date32, nullable |
| PassengerDocument | passenger_document | string |
| BookingCode | booking_code | string |
| TicketNumber | ticket_number | string |
| Baggage | baggage | string |
| FlightDate | flight_date | date32, nullable |
| FlightTime | flight_time | string, местное HH:MM |
| FlightNumber | flight_number | string |
| CodeShare | code_share | string |
| Destination | destination_text | string |

Для каждого поля есть `*_raw` без смысловой очистки. `raw_records.raw_fields_json` хранит весь исходный список полей, включая лишние значения при ошибочной ширине. `raw_bytes_b64` позволяет восстановить точные байты, кавычки и переводы строк; `raw_text` при неверном UTF-8 содержит замены, поэтому для точного восстановления нужны байты.

Происхождение: `record_id`, `source_file`, `source_sha256`, `source_record_number`, `source_line_start`, `source_line_end`, `rule_version`. Номера физических строк начинаются с 1; логические CSV-записи могут занимать несколько строк. Заголовок сохранён в манифесте. `record_id` вычисляется из SHA-256 источника и локатора; он не является ID человека. Основная и сырая таблицы связаны по record_id, issues использует ту же ссылку.

## Правила

- Все идентификаторы читаются строками с сохранением начальных нулей. Для текста удаляются только пробелы по краям; исходное значение остаётся в `_raw`. Нет транслитерации, изменения алфавита или восстановления инициалов.
- Дата рейса допускается только в явном ISO `YYYY-MM-DD` с проверкой календаря.
- Для дат рождения вида `03/04/1980` сохраняются оба календарных варианта в `birth_date_candidates_json`, нормализованная дата остаётся пустой. Если возможен только один вариант либо оба порядка дают одинаковую дату, сохраняется эта дата. `birth_year` сохраняет известный год. Порядок не назначается всему файлу по большинству примеров.
- `field_status_json` содержит статус, правило и объяснение для каждого поля. Ошибки и неоднозначности также записаны в issues.parquet.
- Пустое поле и строковый маркер отсутствия различаются. Маркеры: N/A, NA, NULL, NONE, NAN и «-»; исходный текст сохраняется. **Исключение по смыслу поля: `Baggage=None` — категория багажа, сохраняется строкой.**
- Destination — буквальный текст места назначения, включая сокращённые значения. Он не переводится в код аэропорта, город или страну по догадке. Аэропорт отправления в источнике не указан.
- CodeShare (`Own`/`Operated`) сохраняется как категория источника; фактический оператор не назначается. Часовой пояс отсутствует, UTC не восстанавливается.
- Неверный UTF-8, синтаксис CSV и число полей сохраняются как проблемные записи; недостоверное выравнивание полей не нормализуется. При незакрытой кавычке границы оставшихся логических записей могут быть неустановимы: их исходные байты сохраняются, но успешное восстановление записей не заявляется.
- Статус `complete` означает завершённое чтение и сохранение байтов; для качества отдельно смотрите `structurally_valid`, статусы строк и issues. Неизвестный заголовок или изменение источника приводит к `failed`.
