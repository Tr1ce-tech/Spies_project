# Разбор документов

```bash
.venv/bin/python -m pipelines.review_documents
.venv/bin/python -m unittest pipelines.test_review_documents -v
```

По умолчанию создаётся новая папка `proceed_data/document_review_v1`. Параметр
`--output` задаёт другой путь; существующая папка не перезаписывается.

Из 3782 блоков билет/дата/рейс выбираются 24: по 6 из каждой комбинации состава
источников и полноты утверждений о дате рождения. Из 2561 удержанного компонента
выбираются 16: по 4 из комбинации конфликта структурированных имён и количества
собственных профилей. Порядок — SHA-256(case_id + версия правила). Выборка
диагностическая; единицы разных типов пересекаются. Это не оценка precision/recall.

CSV читается заново стандартным csv по логическим номерам записей, TAB — по
физическим строкам и независимому срезу полей. Для выбранных документных записей
проверяются документы, имена, даты рождения, билеты, даты и номера рейсов.
Идентификаторы остаются строками. Календарные варианты CSV восстанавливаются
обоими порядками дня/месяца; удобный вариант не выбирается.

Выходы:

- review.html — 40 случаев с первичными значениями, полями для решения и кнопкой
  скачивания JSON. Страница не отправляет данные в сеть. Перед закрытием нужно
  скачать решения: состояние формы при обновлении не сохраняется.
- review_labels.json — пустой шаблон независимой проверки. Технические проверки
  не заполняют метки принадлежности человеку.
- sampling.parquet — категории, размеры рамки отбора и hash-порядок.
- case_evidence.parquet — все сущности выбранных случаев и сверенные поля источников.
- source_audit.parquet — отдельные результаты проверок каждого исходного поля.
- technical_assessment.parquet — совместимость доступных полей, не истинная личность.
- link_evidence.parquet — идентификаторы и исходные утверждения, соединившие компоненты.
- REPORT.md, manifest.json, verification.json — результаты, SHA-256 и проверки.

Метки «подтверждён один человек», «ошибка источника» и «ошибочная связь» требуют
конкретного основания. Отсутствие противоречий или одинаковая дата рождения не
доказывают личность. Без такого основания корректный исход — «Недостаточно оснований».
Форма документа «4 + 6» или «2 + 7» не устанавливает тип или страну документа.

Полные персональные значения остаются локально внутри игнорируемой папки
proceed_data. Источники, текущие группы и признаки модели не изменяются.
