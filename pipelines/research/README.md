# Анализ источников и предварительное сопоставление

Все расчёты локальные. Вход — проверенные результаты семи парсеров; исходники и таблицы парсеров не изменяются.

Из корня проекта:

```bash
.venv/bin/python -m pip install -r pipelines/research/requirements.txt
.venv/bin/python -m pipelines.research --output proceed_data/research_next
.venv/bin/python pipelines/verify_research.py proceed_data/research_next
.venv/bin/python pipelines/build_review_page.py proceed_data/research_next
.venv/bin/python -m unittest discover -s pipelines -v
```

Существующие результаты не перезаписываются. Незавершённый запуск остаётся в `имя.partial/`. Продолжение — той же командой с `--resume`; код, корень проекта и путь должны точно совпадать. Контрольные суммы входов проверяются после вычислений; изменённый вход не получает успешный результат. Успешный запуск удаляет рабочую базу и публикует папку атомарным переименованием. Процесс использует CPU, DuckDB ограничен 2 ГБ и четырьмя потоками; это не жёсткая граница памяти всего Python-процесса.

Текущие расчёты: `proceed_data/research_v1/`. Без персональных значений отчёт и графики скопированы в `reports/source_analysis_v1/`. Локальные таблицы в proceed_data исключены из Git; review_case_members и source_entities содержат персональные сведения.

## Что выполняется

1. Инвентаризация схем, единиц наблюдения и SHA-256 всех входных Parquet.
2. Выделение имён из метаданных JSON; проверка ожидаемой структуры документов. В текущем массиве все паспорта JSON пустые.
3. Отдельные точки привязки исходных записей CSV/TAB/Excel, собственные профили JSON/XML, ссылки на счета YAML. Ни один из этих счётчиков не называется числом людей.
4. Утверждения о документах и картах с исходными значениями и ссылками. В XML код явно напечатан в значении карты, полное название программы сохраняется отдельно. DT не объявляется кодом IATA или оператором рейса.
5. Обзор покрытия и пропусков, выбранных повторов, дат, направлений, узлов сети. Разные единицы не суммируются в пассажиропоток.
6. Компоненты кандидатов по точному документу или паре программа/номер. Пробелы между цифрами документа удаляются без определения его страны и типа; начальные нули сохраняются. Имена — NFC, верхний регистр, пробелы; транслитерация и исправление написаний не выполняются.
7. Проверка всего компонента: различные известные документы, несовместимые варианты даты рождения, имена/пол и неразрешённые варианты свободных имён удерживают весь компонент. Не используется жадный выбор безопасной подгруппы. Неоднозначные даты сравниваются пересечением всех календарных вариантов.
8. Отдельные кандидаты наблюдений по билету/дате/рейсу, возможные пропуски вне блоков идентификаторов, случаи одинакового номера при разных программах, заготовка ручной проверки без истинных меток.

`provisional_consistent` означает отсутствие обнаруженного противоречия по заданным правилам. Это предварительная принадлежность, а не подтверждённая личность. `held_for_review` получает ID компонента кандидатов, но не ID принятой группы. `unlinked` остаётся самостоятельной записью; null group_id нельзя объединять как одного неизвестного человека.

Сильная связь по карте сама по себе не исключает ошибку или использование чужого счёта. Доля принятых компонентов не является precision. Независимых меток нет, precision и recall не рассчитаны. Отбор ручных случаев нацелен на диагностику компонентов, а не на оценку глобального recall.

## Основные таблицы

| Результат | Смысл |
|---|---|
| source_entities.parquet | Профили, якоря записей и ссылки на счета с различимым entity_kind |
| identifier_assertions.parquet | Утверждения источников; raw_value, namespace/value, source_record_id и версия |
| observations.parquet | Все первичные наблюдения; entity_id, дата/рейс/маршрут, единица и происхождение |
| entity_assignments.parquet | Компонент кандидатов и предварительная группа отдельно |
| preliminary_groups.parquet | Проверки и причины удержания всего компонента |
| candidate_block_assertions.parquet | Связь блока с каждым исходным утверждением |
| field_quality.parquet | Null, пустые строки и буквальные маркеры отдельно |
| selected_payload_duplicates.parquet | Список полей диагностической проекции и её повторы |
| source_coverage, daily/monthly/weekday_counts | Знаменатели и распределения отдельно по источнику и единице |
| routes, airport_hubs, route_repeatability | Направления, упоминания аэропортов и повторяемость по датам |
| route_day_support, daily_source_similarity | Внутренняя воспроизводимость направлений/покрытия между источниками |
| route_rank_sensitivity | Изменение рангов направлений после выбранной проекции |
| ambiguous_route_keys, route_conflict_sensitivity | Несколько маршрутов на дату/рейс и сценарий их исключения |
| observation_linkage_sensitivity | Полные объёмы и подмножества по статусу сопоставления |
| review_labels, review_sampling, review_case_members | Пустые метки, основания выборки и материалы проверки |

Поля дат берутся из исходных значений: удаляются внешние пробелы и проверяется ISO-календарь. Исходное значение остаётся отдельно, часовые пояса не назначаются. Коды аэропортов приводятся к верхнему регистру и проверяются только синтаксически; в номерах рейсов также убираются пробелы. Исходное написание сохраняется, фактический оператор не выводится. Маркеры пропуска не превращают категорию багажа None в пропуск.

PDF анализируется отдельно: повторяющиеся правила конца 2018 — начала 2019 нельзя считать вылетами 2017 года. Повторы проекции правил сохраняются с локаторами, а не удаляются как доказанные дубли рейсов. Несколько маршрутов на дату/рейс могут быть следствием многоучасткового рейса или codeshare; это кандидат неоднозначности, не автоматически ошибка.

Происхождение агрегатов восстанавливается по input_hashes, версии кода, source/date/route и соответствующим строкам observations; исходные записи доступны по source_record_id. Полный словарь и схема — DATA_DICTIONARY.md результата.

Замеры performance.json относятся к этапам CPU на данном компьютере. При resume завершённые этапы сохраняют прежние времена; сумма исключает неудачные попытки и не является сравнением CPU/GPU.

Для аэропортов нет универсального преобразования строки NAN в null: исходный код сохраняется, возможная неоднозначность маркера помечается в airport_marker_ambiguity/airport_pair_status. valid_airport_pair проверяет только форму A–Z из трёх букв и не подтверждает существование или историческую корректность аэропорта.

Локальный просмотр ручной выборки: proceed_data/research_v1/review.html. Страница показывает только исходные атрибуты и ссылки, без решения алгоритма. review_labels.csv — редактируемый шаблон; генератор откажется перезаписать его. Личные данные из review.html не входят в публикуемые отчёты reports/source_analysis_v1.
