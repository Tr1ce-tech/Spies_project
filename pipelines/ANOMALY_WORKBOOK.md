# Книга для проверки нормализованных данных

Подготовка аналитических таблиц из корня проекта:

```bash
.venv/bin/python -m pipelines.prepare_anomaly_workbook
```

Результат — новая папка `proceed_data/anomaly_workbook_v1`; существующий набор не
перезаписывается. PDF не читается. Все расчёты выполняются по нормализованным
пассажирским наблюдениям. Конфликты профилей берутся из предыдущего исследования
и явно отделены от новых кандидатов по билетам.

Для построения Excel нужен `@oai/artifact-tool` из рабочего runtime. Создать
временную папку с node_modules, ссылающимся на зависимости runtime, и запустить:

```bash
ARTIFACT_WORKDIR=/tmp/spies-workbook-20261022 node --max-old-space-size=8192 pipelines/build_anomaly_workbook.mjs
```

При отсутствии node в PATH использовать полный путь из загрузчика зависимостей.
`ARTIFACT_WORKDIR` — папка с node_modules, а не путь к самим пакетам.
Книга и изображения для проверки создаются в `outputs/anomaly_review_20261022`.
Папки outputs и proceed_data исключены из Git: книга содержит номера билетов.

Проверка сохранённой книги (Python с openpyxl, только чтение):

```bash
python pipelines/verify_anomaly_workbook.py
```

Проверяются все выгруженные ячейки относительно подготовленного набора, точное
сохранение строковых номеров билетов, даты, сводные формулы, фильтры и закрепление
заголовков. Суточные baseline независимо пересчитываются через Python statistics.
Эти проверки не измеряют эмпирическую точность сопоставления или аномалий.

## Полнота и единицы

В книге полностью представлены сводки источников, месяцы, даты и все блоки с
разными известными документами. Общие блоки представлены подборкой 5000 строк:
сначала больше разных документов, затем больше источников, затем дата/рейс/билет.
По маршрутам показаны до 1000 наиболее частых направлений каждого источника.
Полные таблицы обоих наборов сохранены в Parquet; итоги обзора относятся к полным наборам.
Первичные 4 358 805 наблюдений остаются в normalized_observations.parquet.
Блоки не заменяют эту таблицу и не доказывают принадлежность одному человеку.
Связь к деталям: ticket_key/date_key/flight_key → normalized_observations →
entity_id/source_record_id/source_sha256 → соответствующий источник.

Списки нескольких маршрутов на дату/рейс, одинаковых аэропортов и конфликтов
профилей ограничены в книге 2000 строками. Полные списки сохраняются в Parquet.
Отбор задан явной сортировкой, его размер записан на листах и в workbook_data.json.
Это диагностический просмотр, не репрезентативная выборка. Список повторов тоже
имеет лимит 2000; в текущем массиве повторов выбранных проекций не обнаружено.

Направления учитываются отдельно по источникам; одинаковый маршрут в двух
источниках даёт две строки. Отсутствующие аэропорты не заполняются из чужих
наблюдений. В общем блоке маршрут показывается только при единственной известной
паре. Это сводка известных наблюдений, не поле, подтверждённое каждым источником.

## Диагностические правила

- По датам: число записей сравнивается с медианой того же дня недели в том же
  источнике. MAD — медиана абсолютных отклонений от этой медианы. Показывается
  z = (n − median)/(1.4826 × MAD); флаг при |z| > 3.5. При MAD=0 z отсутствует.
  Используется весь наблюдаемый период; это описательная диагностика, не прогноз.
- Несколько маршрутов: более одной известной пары аэропортов на дату/рейс.
  Многоучастковый рейс, codeshare и ошибки данных остаются возможными причинами.
- Одинаковые аэропорты: origin_key = destination_key. Это повод проверить источник,
  а не доказательство физически невозможного перелёта.
- Разные документы: больше одного известного document_key среди наблюдений блока.
  Несколько документов не доказывают разных людей и не разрешают объединение.
- Повторы: совпадение выбранной source-specific duplicate_key. Это не проверка
  повторов всех исходных полей и не основание удалять строки.

Сезонность, границы периода, зависимость наблюдений и особенности выгрузки могут
объяснять флаги. Порог не калиброван на экспертных метках. Вероятности преступной
причастности, precision и recall не вычисляются. Локальное время не переводится
в UTC, пересадки и невозможные перемещения не реконструируются.

Это снимок. Excel-фильтры, формулы обзора и диаграмма работают с листами книги;
изменение исходных Parquet требует повторного построения набора и книги.
