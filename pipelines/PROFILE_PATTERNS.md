# Паттерны профилей и расхождения документов

```bash
.venv/bin/python -m pip install -r pipelines/profile_patterns_requirements.txt
.venv/bin/python -m pipelines.profile_patterns
.venv/bin/python -m pipelines.verify_profile_patterns
.venv/bin/python -m unittest pipelines.test_profile_patterns -v
```

Запуск из корня проекта, результаты — в новой папке
`proceed_data/profile_patterns_v1`. Параметр `--output` позволяет выбрать другой
путь. Существующие результаты не перезаписываются. Незавершённый запуск остаётся
в `.partial`; продолжение не реализовано, для нового запуска нужен другой путь.
Все данные и модели обрабатываются локально на CPU. PDF не читается.

## Единицы и сравнение

- Локальные профили JSON и пользователи XML анализируются каждый отдельно.
  Даже если их межисточниковая связь удержана, собственный профиль остаётся
  отдельной единицей. Счёт YAML без установленной связи не становится человеком.
- Предварительные группы включают только `provisional_consistent` из research_v1.
  Связи по билетам из normalized_v1 не присоединяют новые сущности к группе.
  Имеющиеся группы остаются предварительными, независимо от результатов модели.
- Локальные профили и группы — альтернативные представления с пересечением.
  Их количество не равно количеству людей и не складывается в такую оценку.
- Когорты определены типом единицы и одинаковым набором источников. Это частичный
  контроль покрытия, не гарантия равных возможностей наблюдения за людьми.

Для модели нужны не менее 5 разных сочетаний дата/рейс и 3 разных дат, согласованный
маршрут минимум у 80% таких сочетаний, минимум 200 единиц в когорте. Остальные
единицы сохраняются с model_eligible=false и не получают отрицательную оценку
«аномалии не обнаружены». У них модель просто не применялась.

Наблюдения одного сочетания дата/рейс внутри единицы схлопываются только для
измерений, независимо от количества источников. Это блок наблюдений, не доказанный
сегмент. При нескольких маршрутах маршрут блока не выбирается. Такой способ
может объединить многоучастковый рейс: raw observations и число вариантов остаются
для проверки. Все исходные наблюдения доступны через observation_members.

## Признаки и модели

Прозрачные правила: высокая наблюдаемая частота, разнообразие направлений,
повтор одного направления, концентрация в окне 7 календарных дней, редкость
направлений внутри когорты. Подробные знаменатели — в REPORT.md и profile_features.

Isolation Forest использует log(1+число блоков), log(1+число направлений), долю
главного направления, долю пикового окна 7 дней, долю пикового месяца и среднюю
редкость направлений. Имена, документы, гражданство, пол и номера карт не признаки.
Score — техническая мера отклонения, не вероятность события.

Проверяемый вопрос: выделяет ли многомерная модель дополнительные сочетания
необычных свойств относительно прозрачных правил? Текущий эксперимент проверяет
воспроизводимость, пересечение списков и чувствительность к seed. Полезность
дополнительных кандидатов должна оцениваться экспертной проверкой с одинаковым
бюджетом на модель и baseline. Независимых меток сейчас нет.

Модель строится на всём историческом срезе, без искусственного train/test по
строкам. Это исследовательский поиск отклонений внутри среза, не проверенная
система предсказания будущих аномалий. Порог 99-го процентиля выбран как бюджет
просмотра примерно верхнего 1% распределения; при совпадающих score доля отличается.
Он не означает, что 1% профилей ошибочны или подозрительны. Точки отсечения не
подбирались по истинным меткам. Значимость и частота ложных срабатываний неизвестны.

Три seed: 42, 43, 44. Jaccard списков помогает оценить устойчивость. Официальное
описание метода: [scikit-learn IsolationForest](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.IsolationForest.html).
Более сложные модели пока не оправданы независимым критерием качества.

## Результаты

- `review.html` — локальный обзор кандидатов и расхождений документов.
- `FINDINGS.md` — подтверждённые результаты, ограничения и сверка документов;
  создаётся независимым проверяющим скриптом. `patterns.png` — график четырёх когорт.
- `profile_features.parquet` / `profile_scores.parquet` — все единицы, признаки,
  знаменатели, eligibility, прозрачные причины, score и устойчивость.
- `pattern_candidates.parquet` / `.csv` — кандидаты по любому правилу или модели.
- `cohort_summary.csv` — объёмы и численность кандидатов по сопоставимым когортам.
- `baseline_thresholds.json` / `model_cohorts.json` — пороги и сравнение seed.
- `feature_reference.json` — медианы и квартили признаков для объяснения отклонений.
  `feature_deviations` в score-таблице описывает два наиболее удалённых признака
  в единицах межквартильного размаха; это не оценка причинной важности для модели.
- `isolation_forests.joblib` — модели собственного запуска, признаки и пороги.
- `flight_day_bins.parquet` / `profile_routes.parquet` / `cohort_routes.parquet` —
  промежуточные расчёты и представленность маршрутов.
- `unit_members.parquet` / `observation_members.parquet` — связь с исходными
  сущностями и всеми наблюдениями через ID, SHA-256 и версии правил.
- `document_discrepancies.parquet` / `document_evidence.parquet` — блоки
  билет/дата/рейс с разными известными документами и первичные основания.
- `held_document_components.parquet` / `held_document_evidence.parquet` —
  удержанные компоненты прежнего сопоставления с несколькими документами.

Последние два вида расхождений пересекаются и имеют разные единицы наблюдения.
Разные документы не доказывают разных людей. И наоборот, совпадающий документ
не доказывает достоверность каждого профиля. Полные личные значения хранятся
только в локальной игнорируемой папке proceed_data. Экспорт в удалённые сервисы
не выполняется.
