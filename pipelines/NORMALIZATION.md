# Общие ключи источников

Запуск из корня проекта:

```bash
.venv/bin/python -m pipelines.normalize_sources
.venv/bin/python -m unittest pipelines.test_normalize_sources -v
```

Вход: `proceed_data/research_v1/{observations,source_entities,identifier_assertions}.parquet`.
Дополнительно читаются `parsers/Tab_Parser/result/flights_part_*.parquet` для проверки
разделения номера рейса по сохранённому фрагменту каждой исходной строки; их SHA-256
тоже входят в manifest.json.
Выход: новая папка `proceed_data/normalized_v1`. Можно задать `--input` и `--output`.
Существующие папки не перезаписываются. Незавершённый запуск остаётся в `.partial`;
повторять его следует с новым путём выхода. Расчёты локальные, CPU/DuckDB.

## Уровни данных

Все исходные столбцы observations и identifier_assertions сохранены без изменений.
Добавлены поля с суффиксом `_key`, статусы и `normalization_rule`.
`source_record_id`, `source_sha256`, `entity_id` и версии предыдущего слоя сохранены.
Правила этой версии зафиксированы ниже; контрольные суммы входов и скрипта — в manifest.json.

`source_entities.parquet` копируется без изменения: имена уже обработаны предыдущим
слоем через NFC, верхний регистр и нормализацию пробелов. Исходное написание имён
доступно в таблице соответствующего парсера через source_record_id. Здесь нельзя
считать нормализованное имя исходным написанием. Кириллица не транслитерируется,
инициалы не разворачиваются, компоненты свободного имени не угадываются.
Наборы возможных дат рождения остаются наборами; один вариант не выбирается.

## Правила cross-source-normalization.v1

| Поле | Преобразование | Статус / ограничение |
|---|---|---|
| date_key | Копия проверенной ISO-даты предыдущего слоя | iso_calendar_valid / missing / unresolved; порядок дня и месяца не угадывается |
| flight_key | NFC, верхний регистр, удаление пробелов; форма: два символа кода, 1–4 цифры, необязательная одна буква | syntax_only_unverified; нули и буквенные суффиксы сохраняются, оператор и codeshare не выводятся |
| TAB flight_key | Только для полной формы `код + 1–4 цифры + YES/NO`: отделить YES/NO | source_compound_split; флаг остаётся в source_flight_flag, его смысл не подтверждён |
| ticket_key | Удалить пробелы; разрешены только цифры | digits_only_unverified; строка с начальными нулями, длина и подлинность не подтверждаются |
| booking_key | NFC, внешние пробелы, верхний регистр; только A–Z/цифры | source_scoped_only; PNR не является глобальным идентификатором человека |
| local_time_key | Строгие HH:MM, часы 00–23, минуты 00–59 | local_clock_only; без зоны и перевода в UTC |
| origin_key / destination_key | Предыдущее нормализованное значение при форме A–Z из трёх букв | syntax_only_unverified; NAN сохраняется в исходных полях, но ключ удержан как неоднозначный маркер; это не утверждение, что NAN не аэропорт |
| namespace_key карты | NFC, внешние пробелы, верхний регистр; явный код 2–8 букв/цифр | Названия программ не переводятся в коды; разные программы не объединяются |
| value_key карты | Только цифры после удаления пробелов | Нули сохраняются, ранее отклонённые утверждения не становятся разрешёнными |
| value_key документа | Проверенный ключ предыдущего слоя | Страна и тип не назначаются, разные документы автоматически не объединяются |

Статусы missing/unresolved различают отсутствие значения и отказ от нормализации.
Оригинальные маркеры остаются в исходных полях. route_status описывает пару аэропортов,
airport_pair_status предыдущего слоя тоже сохранён. Правило нормализации задаёт причину
каждого отказа: например, unresolved для времени означает несоответствие HH:MM.
Для программ и документов key_status дополнительно учитывает исходный usable.

В TAB заголовок содержит соседние FlightCode и Sh. Текущий парсер сохранил весь
`SU1181NO` в FlightCode, тогда как Sh пустой во всех строках. Нормализация выделяет
номер из этой составной строки, не меняя сам результат парсинга. Независимая проверка
фиксированных срезов парсера не проверяла смысл такого разделения: совпадение срезов
не гарантирует корректную семантику полей. Значение Sh требует отдельной документации.

## Таблицы результата

- normalized_observations.parquet — все наблюдения и общие ключи.
- normalized_identifiers.parquet — все утверждения идентификаторов и ключи с пространством имён.
- source_entities.parquet — неизменённые исходные сущности предыдущего слоя.
- trip_candidate_blocks.parquet — блоки наблюдений из нескольких источников по билету, дате и рейсу.
- quality_summary.parquet — численности сочетаний статусов по источникам.
- manifest.json — происхождение, версия, время и сравнение числа блоков до/после.
- verification.json — сохранность числа строк, уникальных ID, всех старых полей и SHA-256 входов; проверка разделения всех TAB-рейсов по исходным строкам.

trip_candidate_blocks не устанавливает личность и не доказывает выполненный перелёт.
observations остаётся таблицей принадлежности к блоку: фильтр по ticket_key/date_key/flight_key
возвращает каждое наблюдение с его происхождением. Разные маршруты и известные локальные
времена подсчитываются в блоке отдельно; разные времена сами по себе не объявляются ошибкой.
Нулевые entity/group ID не используются для объединения неизвестных людей.

Старое сопоставление, review.html и EDA не перезаписываются. Новые ключи ещё не подменяют
проверки всего компонента в research/matching.py. Расширение числа кандидатов не является
оценкой precision/recall; независимых меток пока нет.
